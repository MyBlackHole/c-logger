## 离线校验与恢复

从仓库根目录执行，要求 Python3 标准库具备 lzma：

```sh
python3 validation/evidence/fuzz-20261014/test_verify.py -v
python3 validation/evidence/fuzz-20261014/verify.py
python3 validation/evidence/fuzz-20261014/verify.py --restore /tmp/c-logger-fuzz-evidence
```

恢复目标必须尚不存在。校验器先验证外层/原始 ZIP 摘要、成员数量、
路径、解压限额、成员 CRC 与 SOURCE_COMMIT，全部成功后才写入新目录。
它不调用 `extractall`，不恢复符号链接/硬链接，不执行归档里的任何程序。
恢复目录同时保留原始 ZIP 与按 artifact ID 分组的成员文件。

本轮本地预检：5/5 原始 ZIP 与 GitHub 元数据摘要一致，156/156 成员
恢复后与原始下载内容一致；3 个单元测试组通过，包括四种摘要/身份损坏、
六种非法路径及重复目标拒绝。上述结果只验证归档和恢复机制。

## 不能混同的证据

- 制品含构建产物哈希，但**不含历史 liblogger.a 或 fuzz 可执行文件**。
  无法仅凭本目录恢复那些二进制；重放需检出源码并重新构建。
- #208 原始制品没有 compiler.txt。索引明确记为 null，完整编译器版本
  需要从原运行的作业日志补充，不能由 #209 的环境推断。
- `cov/ft` 是各目标特定插桩构建的反馈计数，不是整库覆盖百分比。
  #208 早期仅入口反馈的 cov=60/ft=76 不属于本归档最终结果。
- 两轮覆盖插桩归档不是未插桩的正式交付包，也不证明任意并发调度。
- 原始 Actions 下载 URL 到期后可能失效；本 Git 副本的校验不依赖下载服务。
- **本次尚未重新运行历史 fuzz 输入。** `verify.py` 固定输出
  `test_replay=not_run`，恢复成功不能写成测试重放成功。
