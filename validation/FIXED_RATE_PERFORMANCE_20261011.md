# 固定到达率与真实文件性能实测（2026-10-11）

## 简要结论

已完成 96 个真实生产静态库样本：1/4 线程、64/1024B 填充、低/中/高计划输入、
`/dev/null` 与容器 overlay 上的真实临时文件，每组 3 轮、每轮 1 秒预热 + 3 秒测量。
全部样本计数守恒、原始延迟分位重算与真实文件逐条核验通过，I/O failed 总数为 0。
这证明测量和输出完整性检查有效，**不是性能达标结论**。

- 21/96 个测量阶段出现 Logger DROP；77/96 个阶段有发生器漏发，其中很多只发生在窗口末尾。
- 轮次差异显著：4 线程/1024B/`/dev/null`/100k 次每秒的三轮 DROP 为 0、174466、0，
  对应发生器漏发 4、11920、7；不能用中位数零丢弃声称稳定无损。
- 1 线程/64B 的 400k 计划速率三轮没有 Logger DROP，但仍有发生器漏发/迟到，
  不等于维持 400k 次每秒的平滑输入或系统理论上限。
- API 调用 P99 与到达迟到 P99 分开给出。全体样本 API P99 范围 1.456–151.489µs；
  到达迟到 P99 范围 0.310–927.333ms。两者衡量不同问题，不能相互替代。
- 真实文件测量阶段的单次排空后 flush/fsync 屏障为 0.002528–0.144449ms。
  这是本容器文件系统整批屏障耗时，不是逐条落盘 P99，更不是物理设备掉电认证。
- 子进程生命周期 RSS 峰值观测范围 81.50–112.98MiB，用户态 CPU 0.127–8.797 秒、
  内核态 CPU 0.515–4.222 秒。包含预热、测量数组、排序/原始数组写出及初始化/销毁，
  不是纯 Logger 资源上限，也不与 3 秒窗口相除冒充业务 CPU 利用率。

当前没有业务 QPS/允许丢弃率/延迟 SLO；数据支持本环境有限窗口的实际边界，
不支持稳定无损容量、跨机器承诺或长期资源不增长。迟到和波动本身不能证明 CPU 限流，
也不能把它们全部归因于 Logger 之外。

## 合同、不变量与性能目标分开判断

- 既有架构/API：生产实现、ABI 和 flush 契约未改；新入口仅通过公开 API 测量。
  静态/共享生产链接与核心功能检查通过，不重新开启生命周期深审或 VM 断电验证。
- 有界配置与计数：队列配置为 65536 槽、INFO 溢出策略为 DROP；发生器的时间/记录数/
  文件与内存预算有上限。本轮每阶段验证 `scheduled = attempted + missed`、
  `attempted = enqueued + sync_fallbacks + dropped`，以及输出完成/成功/失败计数守恒。
  这些是可检查的合同/不变量，不能换算成“理论 QPS 已达标”。
- 性能：完成了固定计划输入下的吞吐/调用分位/迟到/丢弃/整批刷新/资源曲线，
  并观察到高输入压力和部分低输入轮次的异常波动。没有预先存在的数字化业务 SLO，
  所以本次交付以可信测量与实际边界为完成条件，不再设置不存在的门槛使工作无限等待。
  理论最大吞吐、稳定无损容量和生产业务 SLO 不在这批有限窗口数据的证明范围内。

## 低、中、高负载曲线

每行是同一配置的 **3 次实测最小–最大**，各列独立取极值，不构造虚假的配对样本。

“有效输出”=`emitted / output_observed_seconds`，从计划开始计时到输出完成的轮询观测，
不包含后续 fsync；轮询/调度有观测误差。DROP 为 Logger 计数，漏发为发生器计数。

## 复现与安全边界

先按 [基准方法](../BENCHMARK.md#固定到达率与真实文件公开-api) 构建 `bench_fixed_rate`，
并保留实际构建日志与产物哈希。受测配置是静态 release；共享 DSO 的构建/公开符号/
两后端功能 smoke 另行验收，不能声称上面 96 个样本是共享 DSO 的性能数据。

```sh
mkdir -p "$PWD/perf-tmp"
python3 scripts/benchmark_fixed_rate.py \
  --binary "$BIN" --library "$LIB" --build-log "$BUILD_LOG" \
  --out curve-base --threads 1 4 --rates 10000 50000 100000 \
  --payload-bytes 64 1024 --seconds 3 --warmup 1 --repeats 3 \
  --temp-root "$PWD/perf-tmp"

# 同一受测构建：64B 高输入段与 1024B 高输入段各 12 样本。
python3 scripts/benchmark_fixed_rate.py \
  --binary "$BIN" --library "$LIB" --build-log "$BUILD_LOG" \
  --out curve-high-short --threads 1 4 --rates 400000 --payload-bytes 64 \
  --seconds 3 --warmup 1 --repeats 3 --temp-root "$PWD/perf-tmp"
python3 scripts/benchmark_fixed_rate.py \
  --binary "$BIN" --library "$LIB" --build-log "$BUILD_LOG" \
  --out curve-high-long --threads 1 4 --rates 150000 --payload-bytes 1024 \
  --seconds 3 --warmup 1 --repeats 3 --temp-root "$PWD/perf-tmp"
```

所有命令从固定提交源码执行；`BIN`、`LIB`、`BUILD_LOG` 指向实际受测产物。
脚本拒绝已有输出目录，单样本有 200 万记录/1GiB 预计输出预算、文件与地址空间硬限制、
默认 45 秒生命周期硬超时。只清理自行创建的临时目录，先保存可用的失败证据。
数据文件阶段0为预热、阶段1为测量；排序前保留逐槽位 API/迟到数组，原始字节序也存档。
输出文件逐条检查 phase/seq/填充内容、重复、越界、未尝试记录及 emitted 总数。
