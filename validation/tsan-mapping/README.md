# TSan 映射寿命的运行库实验（#218 / #221）

此目录是独立的检测器运行库修正实验，**不是已经批准替换的项目工具链，也不是 Logger 的生产补丁**。默认借用阶段14仍有同步 fork 用例失败；本实验不增加跳过、不改现有 TSan 门禁，不自动关闭该阻塞。

LLVM固定提交 `3b5b5c1ec4a3095ab096dd780e84d7ab81f3d7ff` 对应 llvmorg-18.1.8。其 mmap 拦截器只模拟新写入，而 munmap 路径另调用 UnmapShadow 清理同步元数据。MADV_DONTFORK 的内核页排除没有经过用户态 munmap，因此同地址新锁可能碰到父方旧同步登记。实验在成功 mmap 返回后、向调用方发布地址之前，复用既有 UnmapShadow 再执行原有写入检查。该实现的广义映射、同址对象寿命、锁集合和性能影响仍需审阅，不能凭单个正例批准工具链。

工作流从同一固定上游源码构建原版与候选，只编译一份带插桩的探针目标文件，再分别链接两种运行库；记录版本、原始输出、实际退出码、二进制摘要和补丁。CMake只用于上游compiler-rt，Logger仍使用Xmake。

探针不链接Logger。健康场景要求0退出、无TSan告警且有完整结束标记；原版的held场景要求66退出并有锁序诊断；候选held必须无诊断通过。另要求真实逆序、同址新对象的逆序、销毁真实持锁对象、数据竞争全部仍被报告。无关映射和失败mmap不得抹掉存活锁的图信息。held重复16次，其余各1次，共23次/运行库；预期负例不能写成23次正常执行全绿。

`run.py` 拒绝外部TSAN_OPTIONS/LD_PRELOAD/LD_LIBRARY_PATH覆盖，超时、崩溃、缺失结束标记、缺少精确诊断均失败。当前尚无新的运行库通过结论；结果必须引用后续准确提交和实际工作流。
