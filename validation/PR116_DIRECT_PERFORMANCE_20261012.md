## 口径与解释

- 固定队列内存来源于诊断快照，进程 RSS 还含驱动数组和初始化开销。
- P50/P95/P99 是公开 API 调用返回耗时，**不是记录持久化或落盘分位**；
  包含发生 DROP 的调用，不能将过载轮次的尾延迟外推为无损延迟。
- 生产者吞吐按总尝试数/生产结束耗时；端到端吞吐按真实 emitted 数/
  输出全部完成耗时（不包括后续 destroy）。不把出队计数当作输出完成。
- 生产者、文件 I/O、队列等计数守恒是硬判定；由新驱动和独立判定器
  验证真实实验输出。脚本退出非零/超时/错误构建均失败，不通过
  continue-on-error 掩盖。吞吐比值与尾延迟为审阅证据，不以缺失的
  业务 SLO 推定“性能达标”或自动回退。
- GitHub Actions 的逐轮 JSONL、CSV、环境和构建日志由工作流上传，当前
  保留期为 30 天；本文仅保存可长期阅读的结论和可重复执行的提交引用。
  原始制品到期不能解释为证据仍可直接下载。

## 范围与后续

此对照补齐 #116 的原子唤醒交接成本观察，并将旧历史趋势与单次修改
的同生产口径实验分开。当前没有足够证据宣称 RMW 在所有负载无回退；
若要设定严格业务 QPS/P99，须指定实际目标硬件、输入/持久化语义与
可接受丢弃率，再在独占或可控制环境里做长期验证。

保持当前 RMW 运行时代码不变，也不为取得有利数字人为隐藏 DROP。
相关文档纠错已由 #127 / PR #195 完成；本轮只增加测试工具与证据，
不修改公开 API/ABI、运行时日志协议或发布标签。
