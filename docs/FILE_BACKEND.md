# 文件后端契约：单所有者 / 固定目录 / 不覆盖轮换

> 现行设计入口见 [v2/README.md](v2/README.md)。本文保留的 Audit 专属名称、结构与行为仅为历史背景；
> Audit/密码学模块已退役，不属于当前 API、对象图或验证范围。普通 Logger 条款仍适用。

本版在宿主持有版本上加固文件资源，不接管第三方进程或线程模型。
这是当时开发版的兼容性收紧。

## 支持范围和兼容性变化

- `LOGGER_OUT_FILE` 的普通文件目标现在只有一个协作所有者。无论 NONE、EXTERNAL
  还是内部轮换模式，第二个独立实例都被拒绝；共享目标应共享同一个 `logger_t *`。
- 独占锁是 `<active basename>.logger.lock` 上的非阻塞 Linux `flock`。
  同进程不同 `open`、跨进程及父目录路径别名都会争用同一个锁 inode。
  冲突返回 `EBUSY`。不使用全局对象注册表，也不使用会受同进程其他 fd 关闭
  影响的 POSIX 记录锁来实现这个普通文件所有者。
- 常驻锁文件创建权限请求为 0600（仍受宿主 umask 约束）。创建普通日志现在需要
  创建/访问协调文件的权限，不再只要求对已有活动文件具有追加权限。
  库从不 unlink 协调文件；运维不得在所有者存活时删除/替换它。
- 活动文件和协调文件最终路径不允许符号链接或硬链接（`ELOOP` / `EMLINK`）；目录
  祖先可在初始化时经过符号链接解析，之后绑定到实际目录 fd。同一个目录的不同
  路径写法不会创建不同所有者。
- 普通活动文件的基本名称不得以 `.logger.lock` 结尾。该后缀属于文件后端内部协调
  命名空间，拒绝它可防止另一个合法 Logger 把正在持有 flock 的协调 inode 当成日志
  活动文件并在轮换时替换路径。
- 内部轮换仅支持普通文件。FIFO、套接字、目录等拒绝；字符设备仅 NONE 模式接受，
  用于如 `/dev/null`、`/dev/full` 管线测试，不是持久化保证，fsync 仍可能返回 EINVAL。
- 空路径、末尾斜杠 / `.` / `..`、过长路径/文件名返回错误，绝不截断再打开。
  基本名称还须为 `.logger.lock` 与内部轮换的 24 个字符扩展留出空间。
- 操作者必须拥有和信任日志目录及祖先；整个目标的归档命名空间归同一个所有者管理。
  不允许把另一个 Logger 的活动文件故意命名为本目标的归档文件。

**协作锁不是安全防篡改机制。** 不支持忽略协议的写入者、恶意替换 inode、绕过锁的
外部写入、跨版本不遵守此锁协议的写入者，也没有验收 NFS/SMB 的分布式锁语义。
子进程继承的 flock 描述符引用可能延长锁寿命，直到全部引用关闭；CLOEXEC 会在 exec
时关闭，不表示 fork 就关闭。现有原始 fork 防护不在本轮放宽。

## 固定目录，不跟随后来的 cwd

普通文件初始化时打开父目录 `O_DIRECTORY|O_CLOEXEC`，保存基本名称。后续 open、重新打开、
重命名、保留和目录同步使用同一个 dirfd；宿主后续 `chdir()` 或父目录改名，不会
将日志切换到另一个同名目录。应用不应在初始化正在解析多个配置路径时并发改变 cwd。
原始完整路径只用于诊断，不用于重新解析文件操作。

内部轮换前核对活动文件描述符和目录项的 dev/ino。活动文件被外部替换时返回 ESTALE，不
归档另一个文件。使用外部 logrotate 时，应选 EXTERNAL 并由宿主安排重新打开，不要让
内部轮换和外部工具并发管理同一个活动文件。

## 时间归档不覆盖

保留已有命名：`xxx.<UTC时间>.log`、`xxx.audit.<UTC时间>.log`；不改成 `.1/.2`。
归档调用 Linux `renameat2(..., RENAME_NOREPLACE)` 系统调用：目标存在时 EEXIST，绝不
覆盖。相同时间或时钟回拨，在当前实例最后成功候选之后以微秒递增重试，最多 1024 次。
文件名时间因此是用于唯一命名的逻辑时间候选，不保证等于精确的墙上时钟事件时间。
达到上限返回 EEXIST，不忙等、不退回普通重命名。

该能力要求内核及文件系统支持 RENAME_NOREPLACE。系统调用不存在/标记不支持时返回
ENOTSUP；没有覆写式重命名或 link/unlink 的静默回退。使用系统调用避免引入
新的 glibc renameat2 包装器版本依赖，但**不表示所有 Linux 3.x 文件系统已兼容**。
创建 Logger 成功不代表所在文件系统支持将来的内部轮换；不支持的平台应禁用内部轮换，
使用宿主协调的 EXTERNAL，或显式处理轮换失败。

轮换顺序：

1. 确认所有者/活动文件身份；同步旧数据及尚未确认的目录状态。
2. 不覆盖地归档旧活动文件；标记旧 fd 已分离，之后禁止向它追加。
3. 同步归档目录；以 O_EXCL 创建新活动文件。
4. 同步新空文件与目录后切换到新 fd，关闭旧 fd。
5. 按严格名字、普通文件/单链接规则做保留，并同步删除结果。

步骤 2 后发生错误：保留旧 fd 供清理/诊断，但它已属于归档，后续写调用拒绝，不能把
历史归档继续当活动文件。普通 Logger 可以由宿主显式重新打开恢复输出位置；此前锁存的
I/O 错误不会被抹掉。Audit 仍按 IO_FAILED 策略停写，不开放就地重试受保护业务。

这些步骤不是跨文件事务。归档成功后新活动文件打开失败，目录结构可能已改变；返回
失败不表示所有文件操作回滚。测试的 `_exit` 模拟进程退出，不等价于真实掉电测试。

## 重新打开

- 先打开和验证新候选 fd，失败保留原 fd、大小及身份。
- 成功候选需在切换前确认旧文件同步和目录同步；失败仍不关闭旧 fd。
- 成功切换后才关闭旧 fd。关闭失败返回错误，但新 fd 已安装；不重试旧 fd 号码。
- 新文件可能在稍后同步失败前已被创建，不能承诺重新打开失败无任何目录副作用。
- 失败记录进实例 first_error；后续重新打开或日志输出成功不会清除历史错误。
- 最终处置无论哪一步失败，都继续关闭数据、所有者、目录三个 fd，保留首个错误。
  显式 `logger_destroy(&owner)` 仍在普通错误下释放对象，不可重用指针。

## Audit 联动

Audit 先预留活动文件的普通所有者，然后才读取、核验或修复历史；恢复不会先碰到
别的普通 Logger 已持有的活动文件。预留没有打开/创建活动文件，保证拒绝恢复或
算法失败不被提前的活动文件创建掩盖。恢复成功后把预留移进同步 Logger，
不存在发布/重新获取的写入者窗口。

检查点目标也有独立 `.logger.lock` 预留；不同名字共享一个显式状态路径时会冲突。
Audit 不再维护第二套 `.audit.lock` 协议：活动文件日志在恢复前取得的文件后端
所有权本身就是写入者租约，恢复成功后该预留直接移动给同步 Logger，
因此从恢复开始到关闭始终不存在第二个协作写入者可以取得同一活动目标的窗口。
这也避免在同一对象上长期维护 flock 与 fcntl/OFD 两套所有权协议。

Audit 恢复和检查点直接使用文件后端所有者已持有的 `dir_fd + basename`。
归档枚举通过 `fdopendir(dup(dirfd))`，文件访问/身份检查/提交 分别使用
`openat/fstatat/renameat/unlinkat`。初始化完成后不再通过 `/proc/self/fd` 把 fd 重新
转换成路径名，也不依赖 procfs。父目录重命名或 cwd 改变不会改变本生命周期绑定的
目录身份；目录本身仍属于受信任部署边界。

普通文件实例常驻 3 个 fd（数据、目录、所有者），比之前增加 2 个。启用完整性保护的
Audit 常驻约 5 个文件/目录/锁 fd；检查点/证据临时 I/O 另计。没有
每条日志新增长期资源或新工作线程。本轮没有重新测量吞吐，更多轮换同步可能增加延迟。

## 全局便利层的联动修复

全局 Logger 创建前先检查 EALREADY，控制互斥锁串行初始化与完整旧实例处置。
这避免重复初始化 先创建候选文件，也避免旧所有者尚未释放时新默认实例抢占文件锁。
本轮不宣称所有 Global API 准入/代次/取消语义都已完成发布审查。

## 本轮验证环境的持久化限制

实际运行目录所在的 OverlayFS 挂载带有 `fsync=volatile`，原始挂载信息见
`validation/file_backend/environment.txt`。因此本轮通过的是调用顺序、错误传播、
命名空间操作、资源清理和真实进程退出后的恢复验证，**不是介质掉电持久化验收**。
Linux OverlayFS 文档说明 volatile 模式省略对上层文件系统的同步，不能保证
系统崩溃后的数据留存。普通 Logger 基本 API 发布验收保留参数/返回值、并发、资源、
轮转、正常 flush/关闭语义和进程 SIGKILL 故障回归；当前不维护 VM/断电测试，
专用测试程序、脚本及 CI 已移除。若部署另外要求介质掉电保证，应在其真实目标文件系统、
非 volatile 挂载与存储栈上另行验证。既有 flush/fsync 契约不变；本库不能用更多
fsync 抵消文件系统主动关闭持久化的挂载策略。

参考：https://docs.kernel.org/filesystems/overlayfs.html#volatile-mount
