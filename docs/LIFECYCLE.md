# 对象与子系统生命周期

> 现行设计入口见 [v2/README.md](v2/README.md)。本文保留的 Audit 专属名称、结构与行为仅为历史背景；
> Audit/密码学模块已退役，不属于当前 API、对象图或验证范围。普通 Logger 条款仍适用。

生命周期定义合法的状态转换、发布点以及最终销毁。所有权和清理都必须服从这一模型。

## Logger 实例生命周期

概念流程如下：

```text
分配
  ->
初始化互斥锁/条件变量/后端
  ->
如果是异步实例，初始化队列/工作区
  ->
如果是异步实例，启动工作线程
  ->
RUNNING
  ->
宿主先停止并等待全部外部借用者
  ->
STOPPING
  ->
停止并 join 内部工作线程
  ->
在已有静默期前提下销毁同步对象并检查返回值
  ->
同步/关闭/释放已拥有资源
  ->
STOPPED + 释放对象
```

`logger_t` 在构造完整结束之前不得对外可用。

## 先构造，后发布

通用规则是：

```text
私有分配
完整初始化
验证不变量
发布
```

不要先发布指针，再继续执行可能让其他线程观察到“部分初始化对象”的构造步骤。

## 所有权移交

成功的构造函数只有在返回边界才把所有权转移给调用方。待处理的延迟取消必须在裸指针交给应用之前完成处理。

函数成功返回后，宿主持有显式实例，并负责在销毁之前停止并等待退出所有借用者。
只有宿主了解外部线程及 SDK/插件的借用关系。设置 STOPPING 不是自动排空，
不能在仍有外部原始指针调用时依赖 pthread 同步对象的销毁返回值推断安全。

## 销毁会消费所有权

`logger_destroy_status()` 会消费所有者持有的实例。最终 I/O 过程中即使发生失败，
也不会让该指针变成“可以重试”的对象；实例仍按照文档契约完成销毁。

不得把观察到 STOPPED 状态理解成“已经释放的指针可以重新使用”。

## 全局生命周期

全局阶段为：

```text
IDLE
  -> STARTING
  -> RUNNING
  -> STOPPING
  -> STOPPED
```

一次真实初始化尝试会消费一个代次。被延迟的操作绑定到其进入时观察到的代次，
不得静默转而附着到新的代次。

默认/全局 Logger 从不以“调用方拥有的指针”形式返回；全局操作只会在持有生命周期准入/固定机制期间借用它。

## 工作线程生命周期

工作线程归所属 `logger_t` 所有。

只有异步实例才会创建工作线程，并通过协作方式停止。
工作线程可能访问的资源——包括工作区和队列存储——只有在 `pthread_join()` 成功之后才能释放。
这是**内部工作线程**的退出证明；外部生产者/调用方的静默期由宿主在调用销毁前保证。
两种保证共同构成正常销毁的前提。同步对象 destroy 返回 0 不是使用者检测器：
对仍有持锁者/等待者的 pthread mutex/condvar 调用 destroy 可能是未定义行为。
是否允许最终释放内存取决于此前静默期是否成立，而不是“是否发生过内部错误”。
工作线程内部同步错误（例如 cond_wait 返回错误）若随后 pthread_join 成功，则工作线程已经确定退出，
可以继续安全销毁，同时把该错误返回调用方。只有 join、队列/进度/输出同步对象销毁、
进程存活对象计数等无法证明静止状态/所有权已终止的错误，才必须停止最终释放并保留
退役对象的分配内存。生命周期证明失败不是普通 I/O 关闭失败。

## 后端生命周期

文件/Syslog 后端必须在实例进入 RUNNING 前完成初始化。
重新打开/轮转可能替换内部文件描述符，但两者的提交边界不同。
简单重新打开操作中的候选资源准备失败保留仍可用的旧所有者；轮转成功重命名后，旧 fd
已经属于归档，后续活动文件创建/同步失败进入已分离状态，不能继续写旧归档。
因此不能把两条路径合并为“轮转失败永不改变旧状态”。

## Audit 生命周期

Audit 拥有独立的子系统状态和单写入器所有权。
它的状态机、检查点/恢复以及持久写入器锁不会折叠进 Logger 的词法作用域清理。
Audit 状态转换错误和持久状态写入必须保持显式处理。

## 生命周期证明失败

销毁必须区分两类错误：

- **释放侧 I/O 错误**：对象已经证明没有使用者，可以继续完成最终释放内存，并把
  fsync/close 等错误返回调用方；
- **生命周期/不变量错误**：join 失败意味着内部工作线程退出未获证明；
  同步对象 destroy 或存活对象计数操作失败，是在合法静默期前提下的附加不变量
  错误。两者均按保守策略停止最终释放，但 destroy 成功**不能**推导外部借用者已退出。

公开销毁一旦真正开始仍消费所有者的公开指针；发生生命周期证明错误时，
实现可以内部保留退役对象的分配内存，调用方不得重试或复用该指针。

## 非法的生命周期捷径

禁止：

- 在借用者仍可能执行时释放对象；
- 仅因为状态显示 STOPPED 就复用内存；
- 在没有显式所有权移交的情况下分离工作线程；
- 发布半初始化对象；
- 用 memset 重置 pthread 对象来替代正常销毁；
- 用清理属性替代 join/引用计数/生命周期固定机制。
