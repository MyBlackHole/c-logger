# 全局门面生命周期与取消契约

本轮只收敛可选的应用默认 Logger。第三方 SDK 仍优先借用宿主显式实例或使用
回调；没有默认启动线程，没有新增进程管理、扫描或自动 fork 恢复。

## 内部状态与所有权

默认实例不向用户暴露。一个内部 64 位原子凭据编码代次和阶段，
避免分别读取两个原子值造成不一致组合。每次实际开始初始化候选创建时消耗一个
代次；失败也不回退代次。达到计数上限返回 EOVERFLOW，绝不复用。

```
IDLE --init--> STARTING --成功发布--> RUNNING --shutdown--> STOPPING --> STOPPED
                 |                                                        |
                 +--失败--> IDLE（启动前）/STOPPED（曾关闭） <---再次 init-----+
```

- 控制互斥锁串行候选创建、发布、旧实例完整销毁及文件所有者释放。
- 生命周期 rwlock 在数据/控制入口为实例提供读侧 pin，不让所有生产者串行执行。
- 锁顺序为控制 → 生命周期 → 实例锁；读侧入口不会再获取控制。
- 全局调用不能获得显式指针。显式 logger_t 的销毁仍须由所有者停止并等待退出使用者。

RUNNING 的重复初始化立即 EALREADY，不读取配置内容、不打开候选文件/锁/socket，
不创建工作线程。STARTING/STOPPING 中到达的初始化通过控制锁等待；取得控制后重新
判断是否已有实例。它可以在旧生命周期完整结束后创建新实例，并非热更新接口。

## 全部读侧入口共享准入

覆盖 global_write/LOG_*、刷新/状态、set_level、重新打开、dropped、指标和
I/O 指标。捕获凭据，先检查阶段，再获取生命周期读锁，随后复核同一
完整凭据。此时才使用 g_logger。调用若被延迟到关闭/reinit 之后，不能
写入、修改级别、重新打开或读取新实例，返回/设置 ESHUTDOWN；不自动重试新代次。

阶段结果：

| 情况 | 状态 API / void API 的 errno |
|---|---|
| 尚未成功初始化（IDLE） | ENODEV；仅 LOG_* 保留原有 stderr 启动输出 |
| 正在创建（STARTING） | EAGAIN |
| RUNNING 且凭据未改变 | 使用当前实例 |
| STOPPING/STOPPED，或捕获凭据已失效 | ESHUTDOWN |
| fork 继承状态 | ECHILD，在触及继承锁之前拒绝 |
| 同线程嵌套全局调用 | EDEADLK |

void API 不返回状态，指标在拒绝时为零（errno 区分“无可用实例”与健康的零计数）。
NULL 指标输出维持空操作。logger_set_level 现在拒绝超出 TRACE..OFF 的枚举。
正常成功不覆盖调用者进入 API 前的 errno；成功后的 errno 不作为业务确认协议。

关闭关闭准入之后，新控制读取器也不进入 rwlock，避免持续 metrics/级别
流延长旧读取器集合。已经准入的调用仍完成旧实例操作；等待者复核失败后退出。
这不保证线程调度公平、固定等待时限，或替底层阻塞 I/O 提供超时。

启动 stderr 路径也持有生命周期固定：一条已经开始输出的启动消息完成前，不能
发布新实例；关闭即使没有实例，也等待已有启动输出结束。关闭后不再回落
到 stderr。此便利行为只面向应用，业务 SDK 不应隐式依赖它。

## 关闭阶段的代次与状态返回

新增 `int logger_shutdown_status(void)`，返回 0 或 -1 + errno；原 `logger_shutdown`
调用同一实现并丢弃状态。公开结构布局、原有函数签名没有改变。

1. 控制调用捕获它观察到的代次。
2. 等待控制锁后复核；若已换代，ESHUTDOWN，不关闭新实例。
3. 同一代关闭已完成，返回 0（不会重试已释放实例）。
4. 关闭准入，等待已有读取器，解除发布。
5. 保持控制锁，排空/同步/等待退出/close/释放所有者，之后才发布 STOPPED。

已观察到 STARTING 的关闭可以等待同代初始化结束再关闭；若等待期间又进入
了另一个代次，则拒绝。契约绑定“库入口内捕获凭据”的时点，不是业务线程在
调用函数之前的任意程序时点。

普通 I/O 错误下旧实例仍销毁，状态返回首次错误。重连/后续 I/O 成功不抹掉
该实例历史故障。下一次同代空关闭返回 0，不是此前错误被撤销。新实例可
按正常流程重新创建。不能通过重复关闭重试旧指针或重放业务事件。

## 同步释放与最终销毁的失败闭锁

新增 BROKEN（仅内部）作为**不能证明锁释放或对象最终销毁**的终态。
首次失败 errno 原子锁存，后续所有 Global 入口在接触 pthread 锁或实例前
返回该错误；不能把它当成可重试的 STOPPED，也不得发布下一代 Logger。
闭锁状态仅能随整个进程退出而结束；不新增恢复接口或引用计数。

严格区分两类结果：

| 场景 | 对象是否完成最终释放 | 全局状态 |
|---|---|---|
| 正常关闭 | 是 | STOPPED，可后续初始化 |
| 文件写入、同步或 close 失败，但全部工作线程和同步对象与内部 census 已证明完成释放 | 是，错误仍对外报告 | STOPPED，可后续初始化 |
| 工作线程 join 失败 | 否，保留原对象和工作空间 | BROKEN，不可重新初始化 |
| 队列/实例同步对象销毁失败 | 否，保留依赖存储 | BROKEN，不可重新初始化 |
| 全局生命周期读写锁的读/写释放失败 | 不再进行可能错误的销毁 | BROKEN，不可重新初始化 |
| 全局控制互斥锁的释放失败 | 当前调用不被视为成功结束 | BROKEN，不可重新初始化 |

后端错误与生命周期证明失败都可以返回非零 errno，因此 Global 不能
只通过 logger_destroy_status() 的返回值判定对象是否已经释放，
也不能用全进程对象数做推断（进程可能同时持有其他显式实例）。
新的**私有**销毁回执只有在最终进程对象登记释放并执行 free() 前才置为 1；
不更改公开函数签名、结构体布局或 ABI。

失败对象由 Global 控制器保留在私有的 g_retired 所有权位置。
实例在生命周期写锁下从 g_logger 解除发布，同时转移到 g_retired；
只有真正执行最终 free 的私有销毁回执出现后才清除 g_retired。
因此无法证明 join/同步对象释放安全时，对象内存仍有结构性所有者，
不会变成无法追溯的裸内存泄漏。这里没有关闭泄漏检测，也没有增加
公共引用计数；BROKEN 后不允许从该保留位置恢复 Logger 或重试释放。
初始化候选的回滚同样适用这一转移规则。

如果当前线程的锁释放失败，它可能仍持有该锁：不尝试第二次 unlock，
不释放可能嵌套在内的控制锁，不恢复可取消状态，也不清除 TLS 重入标志。
这是一条**程序同步不变量破坏后的故障隔离路径**，不属于正常运行时
可恢复错误。锁获取失败且没有获得锁，仍可照原契约返回错误并重试。

全局控制器等待生命周期写锁期间，其他读侧调用可能报告释放故障。
失败回滚只能条件性恢复旧凭据，不能覆盖其后发布的 BROKEN；
控制器在获得写锁之后还需重新核验闭锁状态，才能卸载旧对象或发布
新对象。这个检查属于生命周期准入证明，不是普通锁序检查。

对应回归 global_lifecycle_regression 的
release-proof reader/writer/control/join/cond-destroy 五个独立进程场景：
通过链接期替换返回错误，跳过真实不确定释放操作，验证旧对象保留、
其他线程立即被拒绝、没有意外新实例、当前线程取消状态与锁证明一致。

新增 proof-handoff writer/acquire-fail 两个独立进程交错场景：读线程在
持有真实读锁期间被暂停，关闭控制器先发布 STOPPING 并在请求写锁前暂停；
然后读线程实际释放读锁、但链接包装器向调用者报告模拟释放错误，
触发 BROKEN。之后允许控制器继续：一次写锁实际成功，但不得释放
旧对象；另一次写锁获取返回模拟错误，但不得回滚 BROKEN。
这种模拟不声称 POSIX 正常释放后会自然返回该错误，而是专门验证
错误传播和代次状态不可被覆盖。
故障测试不会在资源保留后继续调用已损坏同步对象，也不把模拟故障
当作有效 pthread 对象通常会返回该错误的证据。

## 取消与重入

全局 API 在进入 once/共享锁/实例输出之前暂时关闭 pthread 取消；
释放生命周期/控制和内部 pin，清除 TLS 重入标志之后，恢复原取消状态。
不改变调用者的取消 type。已经禁用取消的调用者仍保持禁用。

- 同步输出、异步 enqueue/回退、等待输出水位的刷新、重新打开、初始化和完整
  拆除均由这层覆盖。取消不是事件/文件/成功发布实例的回滚。
- 恢复 ENABLE 后，挂起取消可立即生效或在后续取消点生效；用户的
  清理处理器此时可重新调用全局 API，不会继承本库尚未释放的全局 pin。
- **阻塞 I/O 或等待很长时，取消也被延迟。没有新增 I/O deadline 或强制线程终止。**
- 防护只覆盖本库全局作用域，不能让任意宿主代码都变成 async-cancel-safe。
- 同线程嵌套调用在拿锁前 EDEADLK，用于 printf/插桩回调误入；不是信号安全保证，
  不支持跨线程回调等待环，也不允许 pthread_exit/longjmp 穿过库调用。
- LOG_* 参数在进入库之前求值，拒绝机制不保护参数求值的副作用/数据寿命。
- **显式实例、Console 的全入口取消和重入仍未完成专项收敛。**

旧显式启用 fork 辅助接口同样获得控制锁，避免旁路与正常生命周期相互覆盖；其
原有单线程前置条件和默认不编译策略不变。原始 fork 的 ECHILD 契约没有放宽。已完成关闭后的重新打开（包括旧辅助接口后）由
此前 ENODEV 收紧为 ESHUTDOWN；初始 IDLE 的重新打开仍为 ENODEV。这是错误语义
变化，不是 ABI 布局变化，调用者不应将 ESHUTDOWN 当成可重试旧实例。

## 与显式入口的联动（后续加固）

显式 Logger、Console 或工作线程内部回调再次进入全局 API 时，在取得控制锁/生命周期锁之前返回 EDEADLK。正常全局 → 显式后端调用仍合法，内层作用域不会提前恢复外层已禁用的取消状态。详见 EXPLICIT_CONSOLE_SCOPE.md。
