# c-logger 2.0 对象与状态机架构

状态：**现行实现的架构设计审查基线**。本文件针对源码中已经存在的行为冻结
对象关系、阶段前提和不得突破的边界；不意味着最终发布审批、业务性能指标或
所有可能调度交错已经验证。#104 设计审查与 #108 公开接口的最终验收应分别记录。

## 1. 产品范围与设计决策

c-logger 2.0 是独立的普通 C 日志库，提供显式实例、全局便利入口、Console、
文件/stderr/本地 Syslog、同步/异步写入、文件轮转、刷新与指标。

- 当前部署对象为 Linux x86_64/ELF64；依赖版本见 [支持矩阵](SUPPORT_MATRIX.md)。
- Audit/密码链、事务恢复、持久检查点与专用物理掉电保证已明确退出范围；
  参见 [移除决策](AUDIT_REMOVAL.md)，不将历史 #105 工作清单当作发布硬门槛。
- 没有必要的独立所有者时，不为 Logger 添加引用计数。Global 选择单控制器、
  代次票据与读写锁固定保护，而不是 RCU/SRCU 或锁类模拟生命周期。
- 每个显式实例拥有至多一个异步工作线程、一个有界队列及输出后端。
  同一实例的日志发送者不是拥有独立内存寿命的所有者。
- 只有可解释的合同才能驱动新原语。泛化 atomic 包装、generic completion、
  seqcount/RCU 当前没有单独的生产使用理由，不因路线图初稿列出就引入。

现行设计不维护 v1 双 ABI、兼容 DSO、fork 重初始化助手或旧 Audit 测试运行时。
更改这些决策必须单独重新进行所有权、风险与公开合同评审。

## 2. 所有权与执行者结构

| 对象 | 结构性所有者 | 使用者和活动范围 | 最终释放依据 |
|---|---|---|---|
| 显式 logger_t | 创建成功后的宿主 | SDK/插件只借用，不接管最终释放 | 宿主停止并等待所有外部借用者；随后由销毁函数退出内部执行者 |
| 全局 logger_t | Global 控制器 | 全局 API 仅在当前代次的生命周期读锁内借用 | 关闭准入、生命周期写锁排空、撤销发布、内部退出与私有最终释放回执 |
| queue / spill pool | 所属 logger_t | 生产者和单消费者；所有存储有界 | 外部生产者静止、内部消费者 join，随后同步对象销毁与释放 |
| worker workspace | 所属 logger_t | 单工作线程私有工作区 | pthread_join 成功；不是通过队列为空推断 |
| 文件 / Syslog 后端 | 所属 logger_t | emit_mu 串行化同实例的写入/重开/指标 | 已排空调用者并完成后端关闭；I/O 失败不自动授权恢复旧指针 |
| Console | 独立的进程级 Console 子系统 | 线程作用域、独立 Console 互斥锁与重入门禁 | 不依赖 Logger 生命周期或自动启动 Logger worker |

[所有权图](OWNERSHIP.md)定义 AUTO、OWNED、BORROWED、MOVED、SHARED
等语义。**生命周期读锁、原子状态、锁类别跟踪、pthread_join、最终释放回执
互相不可替代。** 显式实例的并发销毁仍不受支持。

## 3. 显式 Logger 状态机

| 阶段 | 前置条件与转换 | 允许的操作 / 不允许的推论 |
|---|---|---|
| CREATED / 构造候选 | 完整初始化互斥锁/输出后端，异步时创建队列、工作区及 worker | 不得对外发布未完成构造 |
| RUNNING | 构造者以一次强 CAS 从 CREATED 提交；若 worker 已先报错并转为 STOPPING，CAS 失败并回滚 | 成功创建不保证未来永不发生 I/O 或 worker 错误 |
| STOPPING | 独占所有者调用销毁；已停止所有外部借用者 | 不代表内部 worker 已退出或全部后端记录已持久化 |
| STOPPED / 已释放 | 停止、唤醒并成功 join、同步对象处理、后端释放及存活对象计数完成 | 已消费的指针不能重试、读取状态或交给别的模块 |

worker 启动时状态 CAS 与构造错误优先级见
[工作线程启动](WORKER_STARTUP.md)。已接受写入与正在等待刷新时 worker
失败的处理由 [工作线程失败合同](WORKER_FAILURE.md)定义。

两种错误必须区分：

- **普通后端 I/O 错误**：若已证明借用者和 worker 静止，仍可最终 free，
  错误作为返回值/粘滞指标报告；不能因此重试已经消费的指针。
- **生命周期证明失败**：join、锁释放、同步对象销毁或存活对象计数
  等不变量不能证明，必须保守保留有关分配，不强行 free。
  pthread 同步对象 destroy 返回零也不能自行证明无并发使用者。

此规则同样适用于尚未发布对象的构造回滚，不能只对正常销毁严格要求。

## 4. Global 的阶段、代次与最终释放

Global 保留便利入口，但不把内部 logger_t 所有权交给任何用户。单个 64 位
原子票据同时表示代次与阶段：IDLE、STARTING、RUNNING、STOPPING、
STOPPED、BROKEN。初始化消耗新代次，即使随后失败也不能复用票据。

- 控制互斥锁 g_control_mu 串行创建、发布、撤销与销毁的控制流程。
- g_lifetime_lock 读锁是全局调用的实际借用固定保护：读取票据后
  获取读锁，再重检**完整票据**，仅同代 RUNNING 才访问 g_logger。
- 发布时持有生命周期写锁，先准备完整候选，再设置 g_logger 并 CAS
  提交 RUNNING；失败分支保持控制器唯一外部所有权，不暴露候选。
- 关闭先把同代 RUNNING 转为 STOPPING 阻止新读者；写锁排空已有读者
  后撤销 g_logger，把候选或旧对象交给 g_retired；只有写锁成功释放，
  才可以进入实例销毁。
- 私有销毁回执是最终内存是否实际释放的事实；已 free 后允许传播普通
  I/O 错误及进入 STOPPED，未 free 则锁存 BROKEN、保留对象且拒绝新代次。
- 锁释放不确定时不得再解锁、恢复取消、重新开放准入或销毁可达对象。

[Global R7 阶段证明](GLOBAL_R7_PROOF.md)列出上述转换的线性化点、
额外的独立生产库故障场景、精确发布窗口的白盒注入方法与验收边界。
生产库回归覆盖真实 final free 与相邻并发场景；新增加的
G_STARTING→G_RUNNING CAS 失败测试必须依赖调试/回归归档中的实际
锁类断言暂停点，**不能冒充生产归档本身的精确动态注入**。
其是否通过以本次回归 CI 的精确提交结果为准。

## 5. 有界队列、完成谓词与错误传播

异步模式为多生产者、单消费者（MPSC）结构。预先分配有界槽位和
长消息溢出块，不以逐记录堆分配或无限增长掩盖背压。
队列满时执行配置的 DROP 或 SYNC 回退；丢弃、回退和错误分别有指标。
slot.seq 的 C11 release/acquire 负责负载发布，单原子 RMW 交接负责
唤醒职责，不能以锁类别断言替代语言内存序证明。

以下状态不能合并解释：

- 取得队列位置 ≠ 槽位已发布；预留空洞不能伪造完成；
- 出队/槽位可复用 ≠ 后端完成；
- 后端完成 ≠ 文件 fsync 成功；
- 文件 fsync ≠ 任意磁盘、Syslog 或业务事务的物理持久确认。

flush 捕获目标完成水位，在 progress_mu 保护下检查已锁存
lifecycle_error 与完成谓词，配对使用 progress_cv。
失败可中止等待但不伪造已处理的记录，也不自动释放在途生产者。
正常阻塞 I/O 不承诺固定超时。参考 [队列唤醒证明](QUEUE_WAKEUP_PROOF.md)、
[失败与刷新合同](WORKER_FAILURE.md)及 [内存模型](MEMORY_MODEL.md)。

## 6. 后端统一寿命、分别定义提交点

后端共有 prepare → validate → publish/install → operate → retire →
finalize/destroy 生命周期。**这一共性不表示不同后端具有相同的
替换事务或交付保证。**

| 后端 | 提交与恢复边界 | 失败语义 |
|---|---|---|
| 文件 | 创建时持有协调锁与父目录 fd；重开候选验证完成才替换旧活动 fd | 重开准备失败可保留旧活动目标；内部轮转已完成归档重命名后不能假装旧活动文件未改变，后续失败可能进入 detached 状态 |
| 本地 Syslog | Linux 非阻塞 AF_UNIX 数据报；按 REQUIRED/DEFERRED 启动策略决定是否允许创建离线实例 | 可报告连接/背压/重连与丢弃；没有磁盘重试队列、历史重放或接收端持久确认 |
| stderr / Console | 独立输出锁串行化文本路径，不附带 Logger 文件所有权 | 写入错误可观察；不是事务性持久化后端，不能假装拥有独立安全日志链 |

文件细节见 [文件后端](../FILE_BACKEND.md)；本地 Syslog 见
[Syslog 后端](../SYSLOG_BACKEND.md)；Console 的取消及重入边界见
[显式入口和 Console](../EXPLICIT_CONSOLE_SCOPE.md)。

## 7. 重入、追踪与扩展限制

当前没有额外的生产级内部 trace backend 或需要新建的 trace worker。
内部输出路径不得调用公开 Logger/Console 入口形成递归；同线程显式
重入通过执行作用域拒绝。线程取消只支持延迟取消或入口前禁用取消，
不支持任意异步取消、跨调用 longjmp/pthread_exit 或在信号处理器中调用
普通日志 API。完整规则见 [执行上下文](EXECUTION_CONTEXT.md)。

如果日后引入内部 tracepoint，它不能隐式延长 Logger 寿命、修改用户的
errno/返回值、无界分配或在持有输出/生命周期锁时回调未知宿主代码。
当前没有独立 trace 后端需求，因此没有仅为“完成 trace 清单”而
创建第二套日志实现。
