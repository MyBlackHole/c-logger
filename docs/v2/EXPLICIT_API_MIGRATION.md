# 2.0 新公开 API 与所有权迁移合同（#218 后续）

状态：运行域、显式进程准入、create/destroy、默认槽借用、flush/reopen、Console、四个记录、十二个状态/指标查询及三个 TLS 上下文入口已合入主线。本增量统一 logger_mask_secret 的错误与缓冲区合同，修复重叠拷贝；本增量进一步收口两个级别设置入口，公开错误返回形式已经统一；
正式 ABI 冻结与发布仍取决于最终固定候选的完整验收。

## 目标

* 显式初始化进程域，子进程仅在可信的 fork 快照之后重建；不复活父进程实例。
* 实例采用唯一所有权；借用者只能记录/查询，不能销毁；创建失败不泄露候选资源。
* 统一公开状态接口为 `0/-errno`，不混用 `-1+errno`；**不保持旧 API 源码/ABI 兼容**。
* 对所有权消费与返回错误进行区分，不能仅凭负返回值推断旧句柄仍有效。

## 主线已实现的核心接口

```c
typedef struct logger logger_t;

int logger_process_init(void);
int logger_create(const logger_config_t *cfg, logger_t **out);
int logger_destroy(logger_t **owner);
int logger_flush(logger_t *log);
int logger_reopen(logger_t *log);
```

### 创建

* 准入成功后，`out == NULL` 为 `-EINVAL`，非空拥有者槽为 `-EBUSY`且保留旧值。只接受显式初始化为空的槽，构造失败仍为空；不能盲目清槽泄漏原拥有者。
* 未初始化进程域返回 `-ENODEV`；继承但尚未重建的子进程返回 `-ECHILD`，检查必须先于任何实例锁/候选 I/O。
* 成功完整构造实例并发布 `*out` 后返回 0；失败保持 NULL，原始错误码保留，清理失败另记内部诊断。
* 创建与公开所有权交付之间必须明确取消点：不能在 `*out` 发布后发生隐式取消而遗失所有权。
* 只有进程域初始化入口允许显式失败重试；普通 create 不自动重建进程域。

### 销毁

* `owner == NULL` 返回 `-EINVAL`，`*owner == NULL` 返回 0。
* 调用方先停止所有借用者并等待线程退出。销毁与任何借用调用并发属于调用方违反所有权协议。
* **在任何不可逆销毁操作之前**，先完成进程归属与重入检查；拒绝时保留 `*owner` 原值，返回 `-ECHILD/-EDEADLK`。
* 一旦进入消费阶段，先将 `*owner = NULL`，随后完成排空、关闭、释放；即使 I/O 或最终释放证明失败，调用方也不得再次使用旧地址。无法安全释放时库保留内部退役容器并记录可诊断错误。
* `*owner = NULL` 是独占调用方的写入，不提供并发原子共享句柄语义。
* 销毁过程中取消应被延迟直到所有权消费与内部资源处置完成；若失败返回，应仍可区分“已消费”与“未开始”。
* 子进程不得将父方继承的裸指针传入销毁；失效指针的任意解引用不承诺 `-ECHILD`。

### 日志与刷新

* 四个记录入口均为 `0/-errno` 并保留调用方 errno；普通同步/回退传播输出结果，异步容量DROP为 `-EAGAIN`。发布后的通知错误不证明记录未接受，不能据此直接重试。
* 普通截断仍保留可见标记，严格同步仍在任何后端前拒绝正文/整行溢出。异步接受、后端输出完成与持久化确认是不同事件。
* `flush` 只确认当前实例的既定完成水位与文件同步，不确认 Syslog 持久化或物理断电。
* 默认槽仅借用宿主实例，通过logger_default_set显式绑定/解绑；不会创建或销毁实例。Console是独立终端展示工具，不借用默认Logger，也不拥有第二套Logger。
* 旧 `logger_create` 指针返回、`logger_destroy_status`、void 销毁及全局独立所有权接口最终删除；不提供永久兼容包装。

## 实施顺序与门禁

1. 先修改头文件和可执行 C11/C++11 ABI 快照，编译失败作为强制迁移清单；不能靠双签名包装让测试静默通过。
2. 将 `logger_create` 的内部候选构造与公开 `out` 发布分离，检查失败与取消窗口，补充空 out、未初始化、子方旧域、并发候选、映射/后端逐点失败。
3. 将销毁实现拆为准入与不可逆消费，消费前后分别注入错误，核对指针保留/清空、内部退役计数、fd/映射归还和后继创建。
4. 迁移生产与测试的全部调用点；禁止同时导出旧签名。Global 只保留一条借用/所有权路径。
5. 更新 ELF 符号允许列表、版本脚本、安装消费、文档和发布说明；ABI 破坏明确归入尚未正式发布的 2.0 合同，不能用旧 48 符号快照充当新验收。
6. 在同一提交上跑完整 Xmake 普通/ASan/UBSan/TSan、Linux5.10/glibc2.31、静态共享安装与 fork 父子真实日志。TSan 既有能力跳过单列，不计为覆盖。
7. 最终检查资源所有权、取消、信号安全、异常失败路径、性能回归；只有全部适用门禁通过才合并。无需保持旧 API 兼容。

## 特别风险

* 普通入口的隐式进程初始化已删除；新增入口仍须验证冷状态、初始化中、失败及fork后的准入，不能回退为按需初始化。
* 销毁错误返回不能让业务方误以为旧指针可重试；清空拥有者与不可逆操作之间的取消/信号窗口需实测。
* 跨静态库副本传递裸指针仍不安全；不能把进程代次检查包装成任意失效指针可诊断保证。
* 对同一文件的多进程写入/轮转与进程初始化正交，仍需单独设计。

Console实际合同见[Console接口](CONSOLE_API.md)。记录与查询分别见[记录合同](RECORD_API.md)和[查询合同](QUERY_API.md)：查询统一完整成功才写槽，明确替换六个旧指标入口的失败清零规则；未迁移辅助入口不受此次语义变更影响。
