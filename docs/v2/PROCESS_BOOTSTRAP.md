# #218 第一增量：进程初始化引导状态机

本增量有生产代码与可执行测试，但**不是完整 fork 重初始化实现**。用户要求
不兼容旧 API，后续允许直接迁移签名与错误合同；本阶段没有兼容开关或另一套
注册实现，删除 `pthread_once/register_once/registration_error` 注册路径。
当前实例入口暂时通过同一状态机按需启动；显式初始化成为所有入口前提，以及
create/destroy/默认实例的完整新合同，仍在后续阶段完成，不以此阶段兼容旧 API
为设计目标。没有新建通用原语、句柄墓碑或多进程日志代理。

## 1. 已交付接口与状态

```c
int logger_process_init(void);
```

该接口只取得本进程的引导身份并完成 atfork 注册，不创建 Logger、工作线程、
文件描述符或新的进程运行域。返回值是 `0/-errno`，所有正常返回保留调用方 errno。

| 票据 | 显式初始化 | 现有普通入口的准入 |
|---|---|---|
| IDLE | 单一 CAS 取得 STARTING，再注册 | 进入同一初始化流程 |
| STARTING | `-EAGAIN`，不等待 | 初始化者不是当前线程时等待；READY 快路径不等待 |
| READY | `-EALREADY`，不重置实例或重新注册 | 成功 |
| 正数错误码 | 显式 CAS 取得新尝试，允许重试 | 返回原错误，不静默重试 |
| 当前线程正在注册 | `-EDEADLK` | `-EDEADLK`，避免重入等待自己 |
| 已继承其他进程状态 | `-ECHILD`，先于任何票据等待或 pthread 操作 | 同样拒绝 |

正数票据同时携带错误码，没有“阶段已更新但普通错误字段尚未发布”的组合。
READY 只在 `pthread_atfork` 成功返回后以 release 发布，读者 acquire 观察；
成功注册后不存在回到注册路径的转换。当前首阶段不提供显式重置/注销入口。

fork 子方继承了 STARTING/READY/错误票据都不能直接使用。先发布 owner_pid，
再取得初始化票据；即使 fork 发生在 handler 尚未注册的窗口或更早 child handler
中，PID 不匹配也能在等待/同步前拒绝。对象计数为零不会授权复用旧全局锁。

## 2. 取消与错误边界

在取得 STARTING 前禁止取消。注册返回后先发布 READY 或原始错误，再清除本线程
初始化标记、恢复原取消状态。新接口不承诺自己是延迟取消点；调用方随后到达
`pthread_testcancel` 时，即使被取消，进程票据也不会遗留 STARTING。

禁止取消失败：没有取得票据或注册，可重新尝试。恢复取消失败：已发布的注册
状态不回滚；若注册成功但恢复失败，返回该恢复错误，下一次初始化为 EALREADY。
注册错误与恢复错误同时发生时保留注册主错。异常 pthread 实现、非本地跳转或
在注册过程中终止线程不属于可自动恢复的保证。

普通入口的 STARTING 等待只发生在冷启动，以 sched_yield 等待唯一注册者；
不是实时超时合同，不把自旋次数用于推导线程寿命或初始化完成。当前线程重入
必须在等待前拒绝。完整新 API 迁移后普通调用将改为纯就绪检查，等待不是长期
兼容层。生产热路径没有新增堆分配/工作线程，也没有性能提升声明。

## 3. 验证入口

`xmake test -g process-init -j1`：公开三场景；十二个注册/错误/竞争场景分别
链接白盒归档及（静态配置）真实生产归档。共 27 个静态配置测试、15 个共享配置
测试；生产 DSO 只由公开三场景和安装消费验证，不能用静态包装冒称其内部拦截。
所有计数属于注册项，实际通过情况仍须对应具体提交和运行。

新用例在真实 libc 注册调用前/后暂停，不直接写内部票据；要求精确的 0、
EAGAIN、EALREADY、EDEADLK 和原始错误。重复初始化不得破坏已有多实例。
已有 fork 误用、注册窗口、构造/资源及释放回归继续运行，不删除其断言。

安装后的 C/C++11 消费方真实链接调用新增符号并校验 errno 保留。动态导出为
本阶段 48 个，版本身份仍为未正式发布的 ABI 2；不把新增接口当作最终 ABI 冻结。

## 4. 下一实现阶段及不可扩大的承诺

1. 建立覆盖构造/销毁/轮转候选资源的 fork 协调快照；只有 RUNNING 实例列表不够。
2. 将 Global/Console 等运行态与进程引导状态分离；定义继承 fd 和内存的隔离、
   失败及重复 fork 资源上限，不能只清 forked_child 或 live_objects。
3. 实现子方显式初始化的新运行域，再完成完整新 API 的一次性迁移。
4. 对支持的 Linux/glibc 实际格式化、区域设置、线程创建等调用链独立验证；
   父子同文件/轮转是另一个输出协议，不由引导成功自动解决。

多线程 fork 子方在 exec 前的 POSIX 通用保证仍只覆盖异步信号安全操作。
本增量没有调用子方分配器/格式化/创建线程去假装提供超出该范围的支持。
用户要求的 Linux/glibc 完整重初始化目标仍未完成，不能以本阶段拒绝测试成功结项。
标准依据：[POSIX fork](https://pubs.opengroup.org/onlinepubs/9799919799/functions/fork.html)、
[glibc 进程创建](https://sourceware.org/glibc/manual/latest/html_node/Creating-a-Process.html)。
