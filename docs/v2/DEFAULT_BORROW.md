# 默认实例借用合同

本版本移除拥有型 Global 接口，当前消费方按下述宿主所有权迁移。
代码存在、专项通过与最终候选验收分别记录；本文件不是发布授权。
旧场景适用性映射见 [迁移与测试范围](DEFAULT_MIGRATION.md)。

## 公开接口与唯一所有者

```c
int logger_default_set(logger_t *expected, logger_t *replacement);
```

普通实例仍由宿主持有 `logger_create()` 取得的唯一拥有者槽。
默认槽只借用一个普通实例，绝不调用创建、销毁、flush、join 或后端关闭。
旧 `logger_init()`、`logger_shutdown()`、`logger_shutdown_status()` 的生产声明、
实现与导出已删除，不提供兼容宏或第二套状态机。

| 调用 | 意义 |
|---|---|
| `logger_default_set(NULL, a)` | 当前为空时绑定 a |
| `logger_default_set(a, b)` | 当前为 a 时替换为 b，归还 a 的默认借用 |
| `logger_default_set(a, NULL)` | 当前为 a 时解绑并等待所有默认借用退出 |
| `logger_default_set(a, a)` | 只有当前确为 a 才成功，无新代次 |
| `logger_default_set(NULL, NULL)` | 当前确为空时无操作；仍要求进程准入 |

接口返回 0/-errno，正常返回保留调用方 errno。错误包括：ENODEV（进程未初始化）、
ECHILD（fork 后未重建）、EDEADLK（重入）、EAGAIN（另一个更新已关闭准入）、
ESTALE（期望对象或进入时的代次已变化）、ESHUTDOWN（替代实例不处于 RUNNING）、
EBUSY（替代对象的旧借用尚未归还）、EOVERFLOW（代次用尽）及原始同步错误。

空默认槽上的便利日志返回 ENODEV，不再偷偷写 stderr。显式 Logger、Console、
配置和脱敏接口仍按各自合同工作。其余便利状态 API 尚保留原返回形式，未统一为
负错误码，不能因本候选的单个接口而错误迁移所有错误判断。

## 生命周期前提

宿主在调用期间保护 expected/replacement 的有效寿命，且串行化同一实例的绑定
与显式销毁。参数必须属于同一个进程域、同一实际库实现。此接口不提供悬垂指针
检测，不允许把继承后失效的实例指针作为 replacement。

实例上的 `default_borrowed` 是管理性标记：表示仍有默认绑定、退役读者或尚未
证明归还的默认借用，不是引用计数，也不是实际读者数量。标记为 1 时，
`logger_destroy(&owner)` 返回 -EBUSY 并保持槽；标记为 0 并不替宿主证明其他显式
借用者已退出。正常销毁的独占寿命条件仍然适用。

解绑只等待便利入口的在途调用。异步实例已接受的队列记录继续由其 worker 处理；
不隐含队列排空或持久化。宿主之后显式 flush/destroy。解绑后的旧实例仍是普通
RUNNING 实例，可以显式记录；同样不保证跨不同实例的全局输出顺序。

## 发布、借用与代次

控制锁串行化绑定变更，生命周期读写锁保护默认入口在一个 API 调用中的借用。
顺序仍为控制锁 -> 生命周期锁 -> 实例锁/已有后端锁。读者不能反向取得控制锁；
同线程重入在加锁之前拒绝。

控制操作先捕获进入时的阶段/代次，然后取得控制锁，再复核代次和 expected。
复核在读取或修改 replacement 的状态之前进行。即使同一个实例经历解绑再绑定，
延迟控制请求仍不能穿越指针 ABA。控制方检查代次溢出，再将票据转为 STOPPING，
关闭新读者准入，然后取得写锁等待旧读者退出。

写锁内检查错误状态、标记 replacement 被借用、更新默认指针，以 CAS 发布新代次。
任一延迟读者的解锁错误可以把票据毒化；最终 CAS 不能覆盖 BROKEN。若 CAS 失败，
恢复旧指针，replacement 的临时借用只在后续全部解锁确认后才解除。

读者捕获票据，通过读锁固定寿命后再次比较完整票据。票据变动返回 ESHUTDOWN，
不将延迟记录误写给新的默认实例。没有新增无锁指针返回接口。

## 归还与失败

写锁、控制锁都成功解锁后，才以 release 清除退役对象的管理性借用标记，随后
清除本线程重入状态，再恢复取消策略。任何解锁证明失败都不清标记，不根据
默认指针已移出槽推导对象可释放。相关实例继续归宿主持有，但销毁被 EBUSY 拒绝；
当前没有安全的自动恢复接口，不强行解锁或丢弃对象。失败的绑定层会拒绝后续更新。

在取消恢复失败时，绑定可能已经提交并完成旧借用归还。负返回并不普遍保证“完全
没有副作用”。延迟取消也可能在绑定提交之后发生。宿主的清理处理函数应按预期
实例尝试解绑，再销毁所有者；不要依赖“函数已返回”布尔值，亦不能在解绑失败后
强行释放。新专项实际验证了取消等待者在提交之后的清理顺序。

## fork 与运行域

默认绑定字段与同步对象仍属于不被继承的进程运行域。子方显式重建后默认槽为空，
必须创建并绑定自己的新实例，不能访问旧实例。父方绑定保持不变。此改动不扩大
既有 Linux/glibc 或第三方运行时支持范围。

TSan 对内核排除旧锁映射的模型以及正反校准见 [TSan fork 映射模型](TSAN_FORK_MODEL.md)。
这不扩大未支持的多线程子方 worker 检测能力，也不豁免真实新域锁序或数据竞争。

## 实施与验收边界

新 `default-binding` Xmake 分组覆盖公开冷启动、同步/异步、输出失败、父子独立
绑定、三读者并发替换，以及精确读者阻塞、延迟读者/控制者、ABA、取消、重入、
锁获取/释放失败、取消恢复失败、停机实例和代次边界。针对性错误版本须被实际
运行断言拒绝；它们不是所有 C11 调度的穷尽证明。

当前测试、基准和安装后 C/C++ 消费方均使用宿主拥有者槽。被移除机制的测试不是
自动记为通过：库内创建、销毁、初始回退已不适用；对象回收、取消、故障、默认
读者与发布协议分别由迁移表对应的真实用例承担。最终完整构建、平台与性能结果
必须引用准确候选的实际执行，不能复制上一版结果。
