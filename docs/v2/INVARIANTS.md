# c-logger 2.0 不变量

状态：**逐步冻结**。

当前已冻结的元不变量：

1. 部分初始化的对象不得发布。
2. 最终释放内存前必须证明所有可能使用者已经退出。
3. 证明失败时安全保留/泄漏优先于 UAF。
4. `lock != lifetime pin != join != refcount != atomic`。
5. 用户态并发实现必须满足 ISO C11 数据竞争规则。
6. 热路径资源必须有界，不能用无限增长掩盖过载。
7. 静默截断、静默降低持久性保证、静默降低安全性保证禁止。
8. Linux 内核原语只能由真实问题驱动，不作为风格装饰。

对象级不变量随 #102/#103/#104/#105 逐步补充。


## #102 所有权补充不变量

9. 构造失败回滚与正常销毁一样遵守“先证明安全，再释放内存”；同步对象、工作线程或存活对象计数的证明失败时禁止继续最终释放内存。
10. 引用计数只能用于真实独立所有者；不能为了让裸指针并发销毁“看起来安全”而给每次 API 调用机械 get/put。
11. 从属工作线程/队列/后端不因为跨线程访问就自动成为父对象的引用计数所有者；其生命周期由结构所有者 + 静止状态/join 证明。
12. `inc_not_zero` 的调用者必须已经拥有可安全解引用引用计数字段的生命周期证明，它不能复活或保护一个指向内存可能已经释放的裸指针。
13. 进程级存活对象计数与对象引用计数是不同机制，禁止合并语义。
14. 销毁 pthread 同步对象之前必须先由调用方借用者静止协议和内部工作线程 join
    证明没有活跃使用者；pthread_mutex_destroy/pthread_cond_destroy 的返回值只能作
    额外不变量检查，成功返回不是静默期证明，错误返回触发保守保留而不是强行 free。

## #104 对象与状态机补充不变量

15. 显式实例只向宿主转移一次结构性所有权；公开销毁开始处置后，不再允许外部借用者读取旧指针或重试销毁。
16. Global 读者必须在生命周期读锁内复核完整代次票据；阶段 RUNNING 本身不是内存生命周期固定保护。
17. Global 控制器在生命周期写锁下发布或撤销实例；STOPPING 禁止新准入，写锁负责排空先前读者，内部 worker 另以 join 证明结束。
18. 只有最终释放回执确认实际 free 才能清空已退役实例的结构性所有权；生命周期证明失败进入 BROKEN 并拒绝后继代次。
19. 队列位置预留、记录发布、槽位复用、输出完成、文件同步与设备持久化是不同事件，不得用其中之一伪造另一个的成功。
20. 文件后端重开与归档轮转的提交点不同：重开候选准备失败可以保留原 fd；归档重命名已完成后不得假装旧活动目标仍可写。
21. Syslog 本地发送、Console 输出和文件 fsync 各有独立错误/交付合同；不能统一描述为业务事务已持久提交。
22. 生产无独立 trace backend 时，不为完成抽象清单增加新的递归日志、工作线程或隐藏所有者。未来扩展须重新审查取消、重入、所有权与公开接口。
