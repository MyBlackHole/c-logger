# 记录入口：统一状态与提交边界

本阶段统一现有四个公开记录入口为 `0/-errno`，所有正常返回保留调用方进入时的
`errno`。普通记录入口由 void 改为 int；不增加兼容包装、公开 `va_list` 入口或
新的记录对象。该变化属于尚未正式发布的 ABI 2，使用者必须以同一源码的头文件
和库重新构建。符号名称及数量不变不代表旧函数类型仍兼容。

## 公开入口

```c
int logger_log(logger_t *instance, logger_level_t level,
               const char *module, const char *file, int line,
               const char *function, const char *format, ...);
int logger_log_source(logger_t *instance, logger_level_t level,
                      logger_source_t source, const char *format, ...);
int logger_global_write(logger_level_t level, const char *module,
                        const char *file, int line, const char *function,
                        const char *format, ...);
int logger_log_sync_status(logger_t *instance, logger_level_t level,
                           const char *module, const char *file, int line,
                           const char *function, const char *format, ...);
```

`LOGGER_LOG`、`LOGGER_TRACE/DEBUG/INFO/WARN/ERROR/FATAL` 传回实例记录状态；
`LOG_TRACE/DEBUG/INFO/WARN/ERROR/FATAL` 传回默认记录状态。调用方可显式忽略结果，
但库不再提供独立的丢弃状态包装。内部 `logger_vlog_internal` 只在实现中传递
`va_list` 和错误，不是公开符号。

前三者按实例配置执行普通同步或异步记录。`logger_log_sync_status` 继续是独立
的严格同步路径：不经过异步队列，拒绝不完整的格式并对文件输出执行同步。
它不等待其他生产者的异步完成水位，也不替代 `logger_flush`。

实例参数只借用宿主持有的对象。默认入口在一个代次内取得读侧借用，完成后归还；
空槽不格式化、不输出，不转投后继代次，不拥有或销毁实例。完整生命周期边界见
[默认借用合同](DEFAULT_BORROW.md)和[控制操作合同](CONTROL_API.md)。

## 准入、过滤与错误

进程准入先于实例字段和格式参数读取：未初始化返回 `-ENODEV`，初始化中返回
`-EAGAIN`，失败运行域返回已保存错误，未显式重建的子方返回 `-ECHILD`。
同线程重入返回 `-EDEADLK`。没有成功建立取消保护时返回该错误，不格式化或输出。
这些规则不把失效的旧实例指针变成可在重建后安全诊断的句柄。

就绪后，空实例、空格式和非法消息级别返回 `-EINVAL`；`LOGGER_OFF` 不是合法
消息级别。停止接纳的实例返回 `-ESHUTDOWN`。模块、来源文件和函数允许为空，
继续使用已有缺省标签。输入字符串须在整个调用期间有效且不被并发修改。

参数与状态验证完成后，低于实例阈值的记录返回 0，不调用正文格式化、不获取队列
位置、不输出。空格式不能因为级别被过滤而变成成功。默认槽为空、绑定转换和
取得借用后代次变化分别为 `-ENODEV/-EAGAIN/-ESHUTDOWN`。

正文时间获取、格式编码、同步输出和队列通知错误现在都直接沿调用链返回。
正文中的 GNU `%m` 始终使用公开入口的 `errno`，前置取消、默认读锁、元数据及
成功时钟调用留下的值不能改变它。返回时恢复入口值；调用方应根据 `-rc` 处理
错误，而不是继续读取 `errno` 猜测失败原因。

## 普通记录的接受与完成

| 实际路径 | 直接结果 | 已发生的工作 |
|---|---|---|
| 级别过滤 | 0 | 未格式化、未发布、未输出 |
| 普通同步输出成功 | 0 | 选定输出端已完成本次写入；文件同步仍按既定 flush_level |
| 异步发布及通知成功 | 0 | 记录已经进入队列，后端完成尚待工作线程推进 |
| 队列或正文溢出池耗尽，执行 DROP | `-EAGAIN` | 本记录未发布；原丢弃计数增加 |
| 容量不足，执行同步回退 | 本次输出的 `0/-errno` | 原回退计数增加，不增加 DROP 计数 |
| 发布之后通知失败 | 原负错误码 | 记录已经发布；保存错误并停止后续接纳，不回滚或补写 |
| 已输出后的解锁或取消恢复失败 | 相应负错误码 | 已写字节和已提交记录保留 |

因此 0 不是逐记录持久确认，负返回也不普遍表示没有副作用。同一个 `-EAGAIN`
可能来自准入、容量拒绝或发布之后的通知失败，不能只看数值决定自动重试。
库不会根据失败返回重复发布、同步补写或重放未确认记录。

异步后端错误继续由完成计数、已锁存首错和刷新/销毁反映。当前一次同步记录
成功不会抹掉此前的已锁存错误；后继记录可以成功，而后继 flush 仍报告历史首错。
通知失败已把实例置为 STOPPING 时，后继记录与 flush 在准入阶段返回
`-ESHUTDOWN`；原通知错误仍保存在生命周期错误和首错中，最终由 destroy 返回。
完成、输出成功和文件同步继续是不同事件，不增加 Syslog 远端持久确认或 I/O 时限。

## 普通有界文本与严格同步

返回类型统一不会取消两类记录的原有格式差别：

- 普通正文最多保存 4095 字节，超过上限时以 ` [truncated]` 明示截断，按原路径
  接受；完整行空间耗尽时，在 LF 前放置同一标记。标记成功输出时直接状态为 0。
- 普通异步来源按实际 detail/include_* 需求建立快照；模块、文件基本名和函数的
  上限仍为 127、255 和 127 字节，较长标签末尾使用 `~`。不保留可卸载业务库中的
  来源指针，不新增逐记录堆分配。
- 普通时间转换仍允许可见的 `time-unavailable`；编码或锁错误不能伪装成输出成功。
- 严格同步正文或完整行容量不足返回 `-EOVERFLOW`；非法纳秒返回 `-EINVAL`；
  不规范时间头和编码失败保持既定错误。在这些拒绝发生之前，不调用任何输出端。

边界按字节计算，文本以 NUL 终止，不承诺 UTF-8 码点完整或二进制消息语义。
严格同步可能在部分后端已经输出后遇到真实 I/O 错误，严格格式拒绝不等于输出事务
可以回滚。已有格式、缓存、元数据和计数规则保持不变。

## 收尾错误与取消

普通格式、输出和取消收尾保留首个主操作错误。没有主错时，解锁或取消策略恢复
失败必须作为直接错误返回。不同输出端保持原有执行顺序与首错选择，不因前一输出
端失败而把后续已完成的字节描述成未发生。

默认生命周期锁释放证明失败仍是已确定的安全例外：它覆盖普通 I/O 错误并毒化
默认槽，相关借用不能假装已归还。该规则与[控制操作合同](CONTROL_API.md)相同。
实例输出锁或运行域格式锁的释放证明失败同样保持既有保守保留和封闭行为，不通过
强制重置同步对象来恢复可用状态。

`va_end`、队列发布、临时资源处理和全部可确认的解锁都先于取消恢复；恢复后不再
解引用实例。待处理的延迟取消不会回滚记录。仍只支持延迟取消或入口前已经禁用
取消的调用方，不扩大异步取消、信号处理函数、跨实现副本或并发销毁支持范围。

## 可执行验证

`xmake test -g record-api -j1` 的公开测试使用真实静态库或共享 DSO，四个场景
分别覆盖冷拒绝、同步、异步和真实关闭管道。它们核对四入口的返回值、errno、
显式空实例拒绝、过滤时 `%n` 不执行、普通可见截断、严格超长拒绝及实际文件
记录，没有故障替身。

同一故障驱动 `test_record_errors.c` 分别链接真实生产静态归档和同源白盒归档。
共同场景覆盖时间/编码/写入、取消建立与恢复、运行域格式锁、实例输出锁、主错
加取消恢复错误及 GNU `%m`。默认专属场景另外验证内层取消错误、读锁获取/释放
和安全错误优先；普通记录另外验证真实队列填满、真实溢出池耗尽、同步回退失败
及发布后通知锁/信号失败。

生产格式化故障同时包装 `vsnprintf` 与 glibc 加固入口 `__vsnprintf_chk`，检查
注入确实命中，不关闭生产加固。前置成功操作主动污染 errno，输出字节必须仍反映
调用方值。恢复失败后先核对文件，再执行后继成功调用，不能由后继调用补足缺失。
队列场景暂停实际工作线程、经公开入口填入实际记录，释放后核对恰好一次输出；
溢出池拒绝后短记录仍须成功入队，证明队列本身尚有容量。
通知场景通过真实 `pthread_cond_wait` 与 `wait_mu` 取得睡眠交接；包装器暂缓
真实等待返回后的生产代码推进，提交完成后才恢复，避免伪唤醒先清除 waiting
而使通知故障漏注。发布只执行一次，同时核对直接错误、首错、生命周期状态、
精确输出条数、后继准入拒绝和最终销毁错误。释放证明失败的场景保留存活实例及
其文件和协调锁 inode，直到测试进程退出。

本故障矩阵注入的是取消策略建立与恢复的返回错误；真实 `pthread_cancel`
交接继续由既有显式作用域和默认取消回归验证，不能把两种证据等同。

共享配置中的包装测试仍使用静态支持归档，不是 DSO 内部拦截证据。既有格式、
来源寿命、取消/重入、默认代次、文件/Syslog、SIGPIPE 与 fork 回归继续迁移并保留。
可执行 ABI 快照和旧 void 函数指针拒绝检查覆盖类型变化，安装后 C/C++11 实际
消费者覆盖交付边界。执行结果须绑定准确源码与工具，实际失败、跳过和未运行
分别记录；本文不代表某个提交已经通过最终验收或获得发布批准。
