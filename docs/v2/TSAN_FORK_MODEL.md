# TSan 与 fork 时不继承的锁映射

运行域使用独立MADV_DONTFORK映射。prepare实际取得格式协调锁、资源协调锁；父方
正常逆序释放。内核在子方排除整个映射，没有调用经过检测器拦截的munmap，子方
也不能真实解锁这个不存在且可能被其他分配复用的地址。

## 有限模型通知

仅TSan构建保存有效子方快照中旧域的数值地址。在子方显式创建新域之前，使用
公开`__tsan_mutex_pre_unlock/post_unlock`，按逆序通知检测器旧域的两个持锁关系
已因映射排除而终止。不解引用旧地址，不调用pthread解锁，不真实munmap，不关闭
任何报告、不清空全线程或全部锁图；仅消费一次快照，重试初始化不重复通知。
无效fork快照不会执行该路径，普通/ASan构建也不包含这段代码。

这是“内核排除映射”的检测器模型，不是生产锁的修复，更不是TSan自动证明了此模型。
接口定义见LLVM的 [tsan_interface.h](https://github.com/llvm/llvm-project/blob/main/compiler-rt/include/sanitizer/tsan_interface.h)。
地址型工具接口不能提供任意宿主回调或地址复用下的通用身份证明；因此必须以本库
有效快照、新域构造前且尚未发布的有限入口调用，不在任意旧指针上执行清理。

## 正反验收

`fork_tsan_model`通过Xmake构建并链接真实生产TSan归档；
`check_tsan_fork_model.py`在独立进程中验收三个分支：

| 分支 | 预期 |
|---|---|
| healthy | 父方同步默认绑定；fork后子方重建、真实绑定/写入/解绑/销毁，退出0且无警告 |
| order-error | 同一子方新域的两把真实协调锁建立正确顺序后故意反转，退出66且报告lock-order-inversion |
| race-error | 子方创建两个线程对测试专用非原子变量并发写，退出66且报告data race |

三者必须确认fork时父方只有一个线程，避免检测器对多线程fork后的原生报告忽略。
未插桩程序返回77，校验器必须拒绝，不能当成功跳过。超时、错误返回、缺失诊断均失败。
真实错误故意存在于不安装的诊断驱动中，不进入生产库。现有多线程fork后worker
的31项能力跳过不因这一模型被删除或改记为通过。

本地不链接Logger的最小两锁程序也用作定位：正常互斥锁映射在fork中被排除后，
检测器的旧持锁记录可导致新域假环。该对照不是所有检测器版本的普遍证明；最终
结论必须按准确源码、编译器、运行库和原始结果分别归档。
