# 实例创建与消费式销毁接口

本合同替换当前开发版旧创建签名、void 销毁与 `logger_destroy_status`。
不提供兼容宏、旧符号别名或运行时选择开关。普通默认实例/刷新等其他入口的
进一步迁移另行进行，不能将本增量称为全部公开 API 已统一。

所有使用进程域的调用之前，宿主必须显式 `logger_process_init()` 成功。
未初始化 ENODEV、初始化中 EAGAIN、失败后保持保存的初始化错误；进程准入先于
参数检查。下表中的空槽/参数行为均以进程已就绪为前提，详见
[显式进程准入](PROCESS_ADMISSION.md)。

## 1. 公开函数

```c
int logger_create(const logger_config_t *config, logger_t **out);
int logger_destroy(logger_t **owner);
```

两者成功为 0，失败为负错误码，所有正常返回都保持调用方原 `errno`。
宿主需要 `perror` 时可显式执行 `errno = -rc`；不得直接读取旧 errno 判断结果。
公开 `logger_process_init` 已使用相同返回形式。内部系统调用仍可用 errno，
API 边界负责保留调用方值，不要求整库立刻改成无 errno 的系统调用包装层。

## 2. 创建：成功才发布，禁止覆盖拥有者

`out` 必须指向由调用方独占、可写且已初始化为 NULL 的槽；该槽不能与配置存储
重叠，不可在调用期间被其他线程或信号处理函数修改。NULL 槽指针返回 -EINVAL，
非空槽返回 -EBUSY 并保留原值。它不是替换/热更新接口。

```c
int rc = logger_process_init();
if (rc)
        return rc;
logger_t *log = NULL;
rc = logger_create(&config, &log);
if (rc)
        return rc;
/* log 现在拥有实例；其他模块只借用。 */
```

配置验证、资源失败或被拒绝时不写出部分构造对象。首次、重复初始化以及 fork
子方进程域仍遵守 [运行域合同](FORK_RUNTIME.md)；初次使用和子方重建都必须
显式 `logger_process_init()`，普通调用不再按需建域。

构造在取消被禁用时管理候选。恢复调用方取消策略及处理待定延迟取消时，候选
仍有内部清理责任；取消发生则回滚而不发布。只有该边界结束后才写入 `*out`。
调用成功后发生的取消由宿主自己的清理协议负责。启用的一般异步取消、信号内
调用、跨调用 longjmp 和 pthread_exit 不在支持范围。

## 3. 销毁：公开所有权与物理释放分别判定

调用方先阻止新的借用并等待所有借用者退出。该 API 不自动获得其他裸指针
使用者的静默期，不增加引用计数，也不使并发销毁安全。

| 返回路径 | 调用方槽 | 资源处理 |
|---|---|---|
| `owner == NULL` | 无可写槽 | -EINVAL，无资源操作 |
| 有效空槽 | 仍为 NULL | 0，不注册运行域或重复拆除 |
| 进程未就绪、子方未初始化、同线程重入、取消保护建立失败 | 原值保留 | 入口拒绝，未开始拆除 |
| 正常完成 | NULL | 停止/join、同步、关闭并释放 |
| 普通 I/O/关闭错误 | NULL | 仍消费所有权，保留原始错误 |
| join/锁/同步对象/映射回收证明失败 | NULL | 公开所有权已消费；内部保守保留不能安全释放的分配 |

子方或重入拒绝先于读槽。进入拆除阶段后，库在取消仍被禁用时先取出原值并
清空 `*owner`，再执行不可回滚操作；不会在错误时重新填回旧指针。NULL 只说明
调用方不再拥有实例，**不等于物理映射已归还或工作线程已确认退出**。

保守保留与最终释放的区分继续由内部最终释放回执承担，Global 控制器不能因
拥有者槽已空而错误发布“已经释放”。本增量不设计对半销毁对象的公开重试 API。
所有别名在公开所有权被消费时同时失效；C 本身不能阻止复制别名后违约调用。

```c
/* 外部借用者已全部退出。 */
int rc = logger_destroy(&log);
if (log != NULL) {
        /* 入口拒绝，所有权尚在调用方；先处理拒绝原因。 */
        return rc;
}
/* 无论 rc 是否为 0，都不能通过其他旧别名重试销毁。 */
return rc;
```

## 4. 取消清理

清槽必须早于 `logger_scope_end()` 恢复取消状态。把清槽放到 API 返回之后，
或从返回值推断“错误时仍拥有”，均会给取消清理留下双重释放窗口。
创建的反方向则是恢复/处理待定取消之前不能交出候选。

生产源码不新增测试分支。链接期回归在真实 `pthread_create`、`pthread_join`、
映射释放及取消状态恢复处观察调用方槽，验证边界而不是只看最后返回值。

## 5. 可执行验收

`xmake test -g lifecycle-owner -j1` 注册八种运行场景：正常、I/O错误、入口错误、
join失败、映射释放失败、创建取消、销毁取消、重入。静态配置分别连接真实生产
归档与白盒归档；共享配置白盒仍为静态支持归档，不冒称 DSO 内部拦截。

同组类型测试采用 Xmake 当前 C 编译器验证三个正反对照：旧创建签名、裸指针
销毁、已移除 status 符号。工具/头文件缺失不能算负例通过。安装后的 C/C++11
合同实际调用两个新签名；共享加载测试也确认旧 status 导出不存在。

既有构造40组合、真实回收、Global最终释放、文件/Syslog、fork、取消及安装
消费者均直接迁移新接口，不在生产或测试中添加“旧签名转新签名”的适配层。
历史基准驱动固定使用对应历史源码的接口，不属于本版 API。
结果须绑定实际提交、工具链、通过/失败/跳过数；文档存在不等于测试通过。
