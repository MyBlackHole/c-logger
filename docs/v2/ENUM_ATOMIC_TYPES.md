# 实例状态与日志级别的原子写入类型

本阶段实施 #106/#210 的 D1/T5–T6 在实例状态和日志级别写入上的有限子项。
两种枚举的数值有重叠，原子内建可能在编译器诊断前转换值实参；只看赋给
原子对象的最终类型，不能稳定发现把日志级别误传为实例状态的问题。
当前十处生产写入原本都使用正确枚举，本轮没有复现既有状态机故障。

## 私有参数边界

`src/logger_internal.h` 在真实原子操作外增加五个普通参数函数，并由
同名私有宏在传参前检查枚举类别；指针类型继续由函数参数检查。
对象仍为 `_Atomic logger_level_t` 和
`_Atomic logger_state_t`；不修改 `struct logger` 布局、公开枚举或 ABI。

| 私有函数 | 值与对象类型 | 操作与内存序 | 生产调用数 |
|---|---|---|---:|
| `logger_level_init` | `logger_level_t` | `atomic_init` | 1 |
| `logger_state_init` | `logger_state_t` | `atomic_init` | 1 |
| `logger_level_store_relaxed` | `logger_level_t` | relaxed store | 2 |
| `logger_state_store_release` | `logger_state_t` | release store | 5 |
| `logger_state_try_publish` | `logger_state_t`，含直接转传的 expected 指针 | strong CAS，成功 acq_rel、失败 acquire | 1 |

十处调用分布在 `logger.c` 八处、`logger_global.c` 一处及
`logger_worker.c` 一处，覆盖构造初始化和发布、构造回滚、销毁、
生命周期错误、worker 等待失败，以及实例和默认级别设置。
辅助函数固定现有操作和内存序，不开放任意内存序参数。

GCC 9 没有枚举转换诊断，前置宏统一使用已有的枚举比较诊断：
`sizeof((value) == (目标枚举)0)`。比较结果固定为非变长的 `int`，
`sizeof` 不执行比较或其中的实参；检查位于整个函数调用之前，内联函数
直接接收原始值表达式，仅求值一次。这个位置还保留旧 Clang 对直接
枚举常量参数的转换诊断，避免在值实参内加入逗号表达式后丢失常量来源。
宏内的括号函数名调用原函数，避免重复展开同名宏。
所有工具链使用同一条检查路径，不按版本跳过错误输入。

构造方仍只在 `CREATED` 状态下发布 `RUNNING`。worker 在构造方返回前
发布 `STOPPING` 时，构造 CAS 必须失败；失败 acquire 与向调用方
`expected` 写回实际状态均保留。CAS 清单中的这一项移动到内部头文件，
全树仍为 20 个直接 CAS，扫描规则不放宽。新增真实 helper 的
release/acquire 变异，要求原有内存序门禁拒绝。

配置和 setter 的日志级别值域检查、默认借用固定、错误返回顺序、取消
处理与 errno 保存恢复沿用原合同。函数实参各求值一次，默认入口仍使用
原先取得的运行域。状态的生命周期前提仍见
[工作线程启动](WORKER_STARTUP.md)、[工作线程失败](WORKER_FAILURE.md)
和[生命周期接口](LIFECYCLE_API.md)。

## 编译对照

`tests/scripts/test_enum_atomic_types.py` 从 Xmake 的真实目标取得编译器，
使用 GNU C11 和 `-Wall -Wextra -Wpedantic -Werror`。
测试包含 27 对正反例及 1 个逃逸正例，每套编译器共 55 次语法编译：

- 16 对真实私有头片段：init/store/CAS desired 的错枚举常量与具名变量，
  五个目的原子指针，以及 CAS expected 指针。
- 10 对完整生产翻译单元：在各个真实写点唯一替换值实参；不另写仿制操作。
- 1 对真实构造函数：把 `expected` 的声明由 state/`CREATED` 改为
  level/`TRACE`，数值仍为零，要求错误发生在真实 CAS expected 调用行。

每个反例先要求原正确源码或只修正参数类型的片段成功，再要求错误源码
以正常非零状态退出，值参数出现 `enum-compare`／`enum-conversion`，
指针参数出现
`incompatible-pointer-types`，并包含目标类型。诊断位于宏定义时，
必须由同一诊断的展开链命中准确调用行。缺工具、缺头文件、
无关语法错误、信号终止和超时都不能冒充类型拒绝。
枚举常量的数值重叠由静态断言固定；生产 setter 与配置变量的变异仅证明
类型类别拒绝，不声称每个变量在运行时都与替代值相等。

原始生产写点的本地对照发现：GCC 13.3 拒绝跨枚举值，但接受错类 CAS
expected 指针；Clang 20.1.2 的情况相反。普通参数边界可补齐这两种
工具链，但 GCC 9.4 仍会接受二十个错枚举值反例，因此额外加入上述
不求值的比较检查。Clang 10/18 对枚举常量依赖直接函数参数的转换
诊断；比较与转换检查分别保留，不能因其中一个不报错就接受错误输入。
最低工具链的能力必须由同一测试在对应 CI 实际
执行核定，不能从本地较新版本推导。

## 运行回归与入口

开启 `build_regression_tests=y` 后执行：

```sh
xmake test -g enum-atomic -j1
```

静态和共享配置均注册编译契约与 `enum_atomic_regression/writeback`，
共两个 Xmake 测试项。运行回归包含真实私有头中的 inline，使用独立原子
对象，不链接生产库。它经同名宏调用实际函数，核对失败 CAS 的返回值、对象不变和 expected
写回，直接复用写回值重试成功，并检查成功时 expected 保持原值。
两种枚举的端值经真实 init/store 写入后读回；五个 helper 的六次调用
分别检查对象、值及 expected 参数只求值一次。

这个单线程回归不证明并发内存序或完整状态机正确。真实生产归档的
worker 启动、故障、构造回滚、生命周期与级别错误回归继续独立执行，
完整静态/共享、ASan/UBSan 与 TSan 仍按 [测试入口](../../TESTING.md) 验收。
检测器能力跳过不能计为实际运行通过。

## 明确不保证的范围

这里的类型拒绝依赖编译器诊断和警告即错误策略，不是 C 枚举天然具有
强类型。原始整数、显式转换为目标枚举、已经装入目标枚举的错误外值、
同一枚举中的错误状态和直接原子操作仍可能编译。显式给函数名加括号
可以绕过前置宏，剩余的枚举转换诊断取决于具体编译器。测试明确保留
整数、显式转换、原始原子接口及括号函数名正例，不假定所有编译器都
接受裸跨枚举原子写入或绕过宏后的错类函数参数。

辅助函数不验证值域、状态迁移、对象寿命或并发前提，也不构成跨函数、
别名和全源码写点的通用类型分析。下游停用相关诊断或 `-Werror` 后，
不具有同等编译拒绝保证。其他状态、标志、队列序列和公开整数接口不在
本轮范围。本轮不代表 D1 或 T5–T6 整组完成，不改变发布风险签收、冻结
或正式标签授权。
