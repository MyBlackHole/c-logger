# 默认绑定的完整票据与代次

本阶段实施 #106/#210 的 D1/T4 在默认绑定计算链上的有限子集。
原实现以 `uint64_t` 同时表示阶段与代次组成的完整票据、提取后的代次，
因而不能从参数类型拒绝把代次误传给票据操作。本轮增加不同结构体的
编译约束；源码审查没有复现既有代次溢出或 ABA 防护的生产错误。
当前默认槽的宿主所有权、借用与失败合同见 [默认实例借用](DEFAULT_BORROW.md)。

## 类型范围

两个类型直接声明在 `src/logger_global.c`，不增加跨文件接口或安装头：

| 类型 | 含义 | 使用位置 |
|---|---|---|
| `struct global_ticket` | 阶段与代次组成的完整 64 位票据 | 原子加载后的局部值、读者复核、关闭准入、回滚、毒化与发布 |
| `struct global_generation` | 从完整票据提取的 61 位代次 | 代次上界检查和下一代次计算 |

`phase_of`、`generation_of`、`with_phase`、`rollback_ticket` 和 `phase_error`
接收完整票据；`generation_of` 返回代次，`with_phase` 返回完整票据。
调用方必须在原始整数与这些私有结构体之间显式构造或提取 `.value`。
阶段仍由原有 `enum global_phase` 表示，本轮没有为所有枚举或整数接口
增加全程序类型检查。

`logger_runtime` 中的 `global_ticket` 仍是 `_Atomic uint64_t`，运行域布局、
公开 ABI 和导出不变。加载原始值后构造完整票据；CAS 的 expected 直接指向
票据的 `.value` 成员，desired 显式提取 `.value`，保留失败时的 expected
写回。没有把强弱 CAS、内存序或对象表示改成原子结构体。

## 保留的状态与数值合同

票据低 3 位表示阶段，高 61 位表示代次，最大代次为 `2^61 - 1`。
`with_phase` 只替换阶段；成功的实际绑定变更增加一次代次。
进入时的票据与控制锁内复核票据仍比较全部 64 位，读者在取得生命周期
读锁后也复核完整票据。类型约束没有替代这些运行时的 ABA 和寿命检查。

控制方仍按既有次序复核 expected、处理无操作、验证 replacement，
然后在关闭准入之前检查代次上界。`expected == replacement` 在当前绑定
确实匹配时不消耗新代次；即使代次已达上界，健康运行域中的这条路径仍可
成功。无操作仍受进程准入、重入和同步错误约束。

最大代次下，通过上述前置检查的实际绑定变更请求返回 `-EOVERFLOW`，该路径不改变票据、
默认指针或借用标记。已耗尽且为空的默认槽不能再绑定实例；本轮没有增加
自动清零、回绕、跨域复用或恢复接口。最后一次合法变更仍可把倒数第二
代次上的绑定正常解除，并在全部解锁确认后归还旧实例借用。

关闭准入、毒化、回滚和最终发布沿用原 CAS 协议及全部内存序。
CAS 失败不能覆盖 `BROKEN`，锁失败时的借用保留与首错规则保持原合同。
`validation/cas_orders.tsv` 只同步带 `.value` 的实参表达式，全树仍登记
20 个 CAS；扫描器不放宽，真实生产变异的正反自测继续执行。

## 运行回归

`tests/regression/test_default_binding.c` 增加以下两个独立进程场景。
票据注入只在测试中无并发活动时进行，随后的绑定、解绑和销毁使用真实
生产接口，不在生产库添加测试分支。

| 场景 | 验收内容 |
|---|---|
| `high-generation` | 令代次的第 60 位进入完整票据的最高位，再真实执行 a → b → 空；核对完整票据、阶段、借用归还、默认记录和调用方 errno |
| `last-generation` | 从最大代次减一的 RUNNING 绑定正常解绑，到达最大代次的 IDLE；空 → 空成功且不变，空 → b 返回 EOVERFLOW，随后正常销毁两个宿主所有者 |
| 原 `overflow` 增强 | 最大代次的 RUNNING 绑定拒绝替换后，票据、指针、两个借用标记和 errno 均符合既有合同 |

`last-generation` 不人工还原票据；原 `overflow` 场景为了继续原有健康
清理流程而还原测试注入值，这不是生产恢复能力。场景结束检查实例与
运行域分配回收。既有延迟读者、延迟控制者、ABA、取消、发布毒化、
锁获取／释放失败和十个默认入口的代次回归独立保留。

开启 `build_tests=y` 和 `build_regression_tests=y` 后，
`xmake test -g default-binding -j1` 的静态配置包含 6 个公开场景、
真实生产归档与支持归档各 16 个绑定场景、3 个发布故障场景及编译契约，
共 42 个注册项。共享配置包含 6 个真实 DSO 公开场景、支持归档 16 个
绑定场景、2 个支持归档发布故障场景及编译契约，共 25 项。
GNU `--wrap` 不拦截 DSO 内部，不能把支持归档的注入结果称为 DSO 注入。

`tests/regression/run_default_borrow.sh` 对本次构建的真实静态归档执行
16 个绑定场景、2 个生命周期场景及 10 个默认入口代次场景，共 28 项，
并保存源码身份、实际归档散列、编译器与逐场景原始输出。

## 编译约束与明确边界

`tests/scripts/test_global_ticket_types.py` 使用 Xmake 实际目标选用的
编译器，包含真实 `logger_global.c` 或在该文件唯一位置变异。
每套编译器执行 8 对正反例和 1 个显式逃逸正例，共 17 次语法编译。
每个反例先要求恢复目标实参或赋值表达式的正例成功，再要求错误源码在准确变异行产生
相关结构体的不兼容诊断。缺工具、缺头文件、无关语法错误、信号终止与
超时均不能冒充类型拒绝。四个核心变异分别把代次传入 `phase_error`、
毒化阶段的 `with_phase`、`rollback_ticket`，或重复提取代次。

不同结构体只约束已经迁移的参数、返回值与局部赋值。同型复制、显式取
`.value` 后重建和原始原子接口仍可编译，编译正例明确保留这些逃逸方式。
结构体不验证人为构造的数值是否合法，也不证明调用方选取了正确的票据。
队列槽位序列、完成水位、其他代次和公开整数接口均不在本轮范围。

运行边界、编译拒绝与并发协议分别验收，不互相代替。本轮不代表 D1 或
T4 整组完成，不改变发布风险签收与正式标签授权。
